# Еженедельный мониторинг высокопрочных СМ (РФ + СНГ): регламент прогона

Цель: **лидогенерация** по внедрению сварочных материалов для сталей
с σт ≥ 420 МПа (ступени 420 / 460 / 490 / 550 / 690 / 890+).
Отчёт уходит раз в неделю (понедельник утром, МСК) на Gmail владельца.

Этот файл — инструкция для сессии Claude, которую запускает еженедельная
Routine. Выполнять шаги по порядку и ничего не выдумывать: каждая строка отчёта
должна вести на первоисточник.

## 0. Подготовка

```bash
git fetch origin claude/busy-meitner-xbmoih && git checkout claude/busy-meitner-xbmoih
pip install -q requests beautifulsoup4 openpyxl 2>/dev/null || true
python3 monitoring/tests/test_classify.py   # должен напечатать OK
```

## 1. Прямые сборщики (Telegram t.me/s, hh.ru API, RSS, YouTube RSS, НАКС-дельта)

```bash
python3 monitoring/run_weekly.py --only telegram hh rss youtube naks
```

Если сеть контейнера закрыта (в health.json почти всё `ProxyError` /
`403`), прямые сборщики не работают. Тогда не повторять запуск, а перейти
к шагу 2: веб-поиск через Firecrawl работает и при закрытой сети. В письме
явно указать, какие источники были недоступны.

Первый успешный прогон НАКС-дельты только фиксирует базу номеров свидетельств,
без новых записей. Новые аттестации появляются в отчёте со второго прогона.

## 2. Веб-поиск (Firecrawl): соцсети, СМИ, закупки, СНГ

Для каждого запроса из `monitoring/sources.py → WEB_QUERIES` вызвать
`firecrawl_search` с `tbs: "qdr:w"` (за неделю), `limit: 8`, `sources: ["web"]`.
Только сниппеты; `firecrawl_scrape` использовать точечно, если без полного
текста не определить марку стали или СМ, компанию либо регион. Целую ленту
Telegram-канала через scrape не тянуть: это дорого и раздувает контекст.

Из результатов собрать `extra.json` (в scratchpad) — список записей вида:

```json
{"source": "web:<домен>", "source_type": "web|social|tender|news",
 "url": "...", "title": "...", "text": "<сниппет>", "date": "YYYY-MM-DD",
 "org": "<компания, если ясна>",
 "action": "<конкретный следующий шаг для лидогенерации>",
 "comment": "<почему это лид / оговорки по достоверности>"}
```

Правила отбора:
- Только РФ и СНГ. Зарубежные вакансии и новости отбрасывать.
- Розничные прайсы и карточки товаров — только как ценовой ориентир конкурентов
  (классификатор сам опустит их в класс C).
- Если дата публикации не видна, ставить дату выдачи и писать об этом в `comment`.
- Instagram и Facebook: в РФ Meta признана экстремистской организацией.
  Для B2B-сварки это малополезный канал. Учитывать только то, что пришло
  через поиск, и не строить на нём выводов.

## 3. Discovery: новые источники

Раз в неделю сделать 2–3 поиска вида `site:t.me <тема>` и `site:vk.com <тема>`
по отраслям (краны, карьерная техника, вагоны, мосты, судостроение,
производители СМ). Реально существующие публичные каналы с профильным
контентом дописать в `TELEGRAM_CHANNELS` (имя канала и короткое описание).
Не добавлять каналы, которых не видел в выдаче.

## 4. Сборка отчёта

```bash
python3 monitoring/run_weekly.py --only --extra <scratchpad>/extra.json \
        --notes <scratchpad>/notes.html --save-state
```

(Если шаг 1 отработал, запустить без `--only`, чтобы прямые и поисковые
записи попали в один отчёт.)

`notes.html` — 5–10 строк «Главное за неделю» на русском, в профессиональном
тоне, без воды:
- топ-3 лида: кто, что внедряет, какой класс стали или СМ, предлагаемое действие;
- что изменилось у конкурентов-производителей СМ;
- какие источники не сработали и что это значит для полноты картины.

Уверенность помечать [Точно] / [Вероятно] / [Предположение].

## 5. Отправка

Gmail `send_message`:
- to: владелец аккаунта (адрес из контекста сессии);
- subject: `Высокопрочные СМ: мониторинг <неделя ISO>, A:<n> B:<n>`;
- body: содержимое `monitoring/out/<неделя>/report.html` как HTML.

Если в Gmail нет отправки HTML, отправить простой текст с топ-лидами и
приложить ссылку на файл отчёта в репозитории.

## 6. Фиксация состояния

```bash
git add monitoring/state monitoring/out monitoring/sources.py
git commit -m "Weekly monitoring report <неделя>"
git push -u origin claude/busy-meitner-xbmoih
```

Без этого шага следующая неделя покажет те же сигналы повторно.
